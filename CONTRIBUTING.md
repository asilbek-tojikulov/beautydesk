# Правила работы с репозиторием

## Ветки
- `main` — только стабильные выпуски, каждый отмечен тегом `vX.Y.Z`; прямые коммиты запрещены.
- `develop` — интеграционная ветка; изменения попадают только через pull request.
- `feature/US-<номер>-<кратко>` — задача из бэклога, например `feature/US-07-reschedule-cancel`.
- `bugfix/DEF-<номер>-<кратко>` — исправление дефекта, найденного при тестировании.
- `release/<версия>` и `hotfix/<версия>` — подготовка выпуска и срочное исправление.

Имена веток — латиницей, в нижнем регистре, слова через дефис.

## Сообщения коммитов (Conventional Commits)
```
<тип>(<область>): <что сделано> (<US/DEF/CR>)
```
Типы: `feat`, `fix`, `test`, `docs`, `refactor`, `ci`, `chore`.
Пример: `feat(booking): add cancel with reason (US-07)`.

## Pull request
- цель — `develop`; ревью вторым разработчиком;
- CI (тесты) должен пройти;
- в описании — ссылка на задачу и что проверено.
